# PR #9 返修复审有限整改设计

## 1. 目标与约束

本设计逐条落实《PR9_四问建模返修复审.md》的 F1--F4、机理解释、六张论文主图和交付说明意见。实现继续位于 `fix/independent-review-remediation`，更新既有 PR #9，不新建 PR、不自动合并。

保留已经独立核验的主方程、正式案例、全精度场和事件时间：Q3 正式结果仍为 57.4740097759 h，Q4 正式结果仍为 51.0920106837 h。除非迁移前检查发现归档损坏或数值源码发生实质变化，本轮不重新积分 13 份 Q4 主/验证/敏感性场。

## 2. 输入语义与模型叙事

- 环境观测终点和半径观测终点分别记录为 14,400 s 与 259,200 s，不再共用一个变量。
- 附件2半径在 0--72 h 全程属于实测记录覆盖；正式 Q4 事件位于该区间内，只在观测点间使用分段线性插值，无半径外推、无 1.2 cm 限幅。
- 附录4固定半径 C 组超过 72 h 时仍保持 2 cm，不调用移动半径历史，因此不需要半径外推。
- 附件1水分列统一称为等效边界水分 `Ce`，不称为已经识别的平衡含水率。
- Q1 统一称为“附录2模型：常热物性、非线性水分扩散”，避免“常物性”掩盖 `D(C)`。

## 3. 强制证据闭环

当前报告和论文图实际引用 Radau 方法对照及五个结构敏感性情景，因此两类证据均为强制交付，不采用“缺失时静默降级”的可选策略。

### 3.1 Q4 主验证

- `verification.json` 的运行清单覆盖配置中的全部八个主/验证案例，包括 `diagnostic_only` 的 Radau。
- `verified()` 对每个案例执行 `run.json` 摘要核验和 `load_run()` 递归读取。
- Radau 缺失、身份错误、源码快照过期、NPZ 或接受步损坏均阻止验证、报告、图和便携审计。

### 3.2 敏感性验证

- 敏感性汇总记录每个情景的确切案例名和运行目录，不用通配符猜测身份。
- 公共读取函数重新构造当前配置应有的案例集合，逐项核对情景名、案例身份、配置、生成器、汇总 CSV、`run.json`、NPZ、接受步和源码快照。
- Q4 图、Q4 报告和便携审计复用同一读取函数，避免三套不同强度的门禁。

## 4. 类型化运行归档

`q4.provenance.load_run()` 将 `accepted_steps.csv` 纳入统一返回协议：

1. 严格核对表头与 `TRACE_COLUMNS`；
2. 读取为二维有限浮点数组，要求至少一行、时间严格递增；
3. 作为 `fields["trace"]` 返回；
4. 核对末接受步与 `record.terminal` 的全部同名字段；
5. 核对 `terminal_state`、最后输出时刻、中心/表面/全域最大/平均值及温度范围。

为 `threshold_not_reached` 和 `root_found_post_state_unavailable` 各增加一次真实求解、保存、加载、校验往返。成功事件继续走既有 `check_run()`，并共享底层归档校验。

## 5. 同一物理时刻的近根比较

- 86,400 s 保留但改名为“24 h 中间检查点”。
- 对每一对比较自动取 `min(root_a, root_b)` 之前最后一个共同规则采样时刻。现有 BDF/Radau 对照对应 183,900 s。
- 在该时刻比较全部共同有效固定物理半径和动态表面的温度、含水率，并保存逐列差、最大差、半径和有效列数。
- 该状态直接来自双方精确归档的 60 s 输出，记录取得方法为 `exact_archived_regular_sample`，时间重建误差为 0；不比较各自不同根时刻的末行。
- 全时域最大差、事件时间差、24 h 中间检查和根区间仍分层报告，不合并成统计误差界。

## 6. 机理解释

在相同 `C,T` 下，继续使用

\[
\frac{D_4}{D_3}=0.175\exp(0.15/C).
\]

报告由正式根状态计算并公开：交点 `C=0.0860600`；湿芯区 `D4/D3<1`；更干表层可出现 `D4/D3>1`；正式根表面比值约 3.029，且部分材料节点已经反转。因此 A--D 事件时间差只能解释为物性、几何和空间非线性耦合的净效应。
