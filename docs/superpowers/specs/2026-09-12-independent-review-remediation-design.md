- 工作分支：`fix/independent-review-remediation`

完成标准不是“测试没有报错”，而是审议中的每条意见都有明确处置、权威证据和可复现入口。最终新增 `reports/INDEPENDENT_REVIEW_REMEDIATION.md`，逐项记录结论、文件、命令、指标和状态。

## 2. 保留的主模型与非目标

保留现有一维圆柱径向有效模型：Q1 使用附录 2，Q2/Q3 使用附录 3，Q4 使用附录 4；Q4 采用 `xi=r/R(t)` 的仿射材料坐标。中心对称、表面 Robin 热湿通量、变系数散度、开尔文温度、全域最大含水率事件和动态表面定义均不改变。

本轮不做以下改变：

- 不加入题面未给定的潜热、吸附等温线或气固平衡参数。
- 不给 Q4 干基含水率添加额外浓缩项或重复网格对流项。
- 不用机器学习、复杂优化器或统计置信带包装确定性 PDE。
- 不因为可选效率建议直接替换正式均匀网格；非均匀网格只登记为后续实验，不作为本轮验收门槛。
- 不把数值收敛表述为实物实验准确率。

## 4. 跨平台证据与摘要契约

新增 `common/hashing.py` 作为唯一文件摘要实现，提供：

- `sha256-raw-v1`：用于 NPZ、XLSX、PDF、PNG 和原始题面/附件。
- `sha256-text-lf-v2`：仅用于声明的 UTF-8 文本类型，将 CRLF 和孤立 CR 规范化为 LF 后计算摘要。
- 明确文本后缀包含 Python、JSON、CSV、Markdown、TXT、JavaScript、YAML、TOML；无法按 UTF-8 解码的声明文本直接失败，不回退为宽松比较。
- 每份记录必须携带 `hash_scheme`，读取端不得根据当前平台猜测规则。

`q1.provenance.artifact_sha256` 和 `q2.provenance.portable_artifact_sha256` 保留兼容入口，但内部转调统一实现。Q2 的验证/归档绑定、Q3/Q4 的 `run.json.files`、导出验证、图表清单和审计都使用带方案字段的摘要。

既有数值归档不因纯证据代码变化伪装成重新积分。提供显式迁移入口，先按旧记录验证二进制结果和未变的数值模型源码，再生成 `metadata_migration`，保留旧记录摘要、迁移工具摘要、变更范围和新方案。数值算子、参数或状态数组任一变化时迁移必须拒绝，要求重新积分。

仓库增加 `.gitattributes`，将文本固定为 LF，Office/PDF/图片/NPZ 固定为二进制。回归测试至少覆盖：

1. 同一文本的 LF、CRLF 和 CR 版本摘要一致。
2. 任意非换行字符变化被拒绝。
3. 二进制任何字节变化被拒绝。
4. Q2 报告、Q3/Q4 归档在 LF 检出和 CRLF 副本中均可读取。
5. Git 归档 ZIP 解压目录没有 `.git` 时仍完成全部便携证据检查。

## 5. Q4 数值验证重构

### 5.1 算例配置

`configs/q4.json` 将算例的网格、物性、几何、积分方法、容差倍率、步长倍率、半径插值、环境模式和最大时域显式记录。验证组分为：

- 空间组：附录 4 收缩、linear、末小时均值、同一基础 BDF 设置，`N=5120/10240/20480`。
- 时间组：同一 `N=20480`、同一物理问题，比较基础 BDF 与收紧容差并减半最大步长的正式 BDF。
- 方法组：在可承受的相同网格上比较 BDF 与 Radau；若 Radau 因资源失败，必须保留失败状态，不能删去算例后声称通过。Radau 是独立诊断；只要正式网格上的基础/收紧 BDF 时间门禁通过，单独的资源失败不否决正式结果。
- 退化组：附录 3 固定半径与 Q3 同网格结果比较。

正式结果继续采用附录 4、收缩、linear、末小时均值、`N=20480` 收紧 BDF。空间组最细层不再同时改变时间设置。

### 5.2 比较对象

`q4.validation.compare` 比较：

- 所有共同的 60 s 时刻；
- 一个预先配置、早于全部事件的统一末态时刻；
- 21 个固定物理半径在两算例都处于域内的单元；
- 第 22 列动态表面；
- 温度、含水率、全域最大值、最大值位置、平均值和事件时间。

每个最大差记录数值、预算、时间、列名、物理半径和是否为动态表面。空间差、时间差、方法差和根括号宽度分别报告，不再相加后冒充“总误差”。

## 6. Q4 输入与结构情景

`RadiusHistory` 增加显式 `linear`/`pchip` 模式。两种模式都必须精确通过观测点，并在密集检查网上保持半径有限、正值、非增。禁止默认多项式外推。

linear 继续作为正式模型，PCHIP 只用于结构敏感性；两者都属于观测点间假设，不能因为 PCHIP 更平滑就称其更真实。

新增 `configs/q4_sensitivity.json` 与 `q4/sensitivity.py`。所有情景使用同一网格、积分器和误差设置，仅改变一个结构输入：

- linear 与 PCHIP。
- 半径记录精度上下界：按配置的半个最小显示单位整体扰动，保持初始半径、正值和非增；这是情景范围，不是随机误差或置信区间。
- 4 h 后末小时均值保持与末值保持。

每个情景保存完整身份、事件时间、根状态、关键场差和运行摘要。报告同时给出情景效应与该网格的数值分辨率，避免把约 12.6 s 的插值效应与亚秒数值误差混为一谈。

## 7. C 组完整事件与运行状态

附录 4 固定半径 C 组不依赖附件 2 在 72 h 后的移动半径，因此将固定半径保持为 2 cm，并把环境按正式规则延拓至足以括住事件的配置时域。预计事件约 130 h，但程序只依赖配置和实际括区间，不写死答案。

求解器引入类型化结果/异常：

- `ThresholdNotReached`：积分成功到时域末端，但未发生向下穿越。
- `StrictPostStateUnavailable`：已找到根，但配置时域不足以覆盖根后严格状态。
- `IntegrationFailure`：数值积分失败或状态非法。

未达标运行也保存终态、时间、`Cmax`、`g=Cmax-0.15`、最大值位置、表面/中心/平均值、接受步、二进制摘要和来源摘要。读取端对成功和未达标记录执行同等来源及产物验证。

C 组完成后，以相同 `N=5120` 的 A/B/C/D 事件时间计算主效应和交互项；只有四个事件全部存在时才生成精确交互，否则输出下界表达并阻止精确交互字段出现。

## 11. 错误处理与缓存规则

- 每次运行先写 `status=running`，成功后原子替换为终态记录；异常保留 `failure.json`。
- 缓存命中必须同时满足输入、配置、数值源码、产物摘要和状态类型。
- 配置或数值模型变化后不得仅重做验证；受影响算例必须重新积分。
- 纯报告、绘图或工作簿样式变化只重做对应交付层，不伪造新的数值运行提交。
- 正式导出只接受全部强制数值门禁通过的正式算例；敏感性失败不覆盖正式主结果，但必须如实记录。
